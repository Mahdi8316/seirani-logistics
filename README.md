# سایت شرکت ترخیص گمرکی و بازرگانی بین‌الملل

وب‌سایت تک‌صفحه‌ای، **RTL فارسی** و اسکرول‌محور برای شرکت ترخیص گمرکی و بازرگانی
بین‌الملل. مخزن شامل دو نسخه است:

- نسخهٔ Next.js در ریشهٔ پروژه، مناسب توسعه با Node.js.
- نسخهٔ PHP/MySQL در `php-site/` که نسخهٔ مورد استفاده روی هاست فعلی است.

فایل‌های محیطی، دیتابیس، تنظیمات واقعی PHP، بکاپ‌ها و بسته‌های استقرار عمداً وارد
Git نمی‌شوند.

## پیش‌نیازها

- Node.js نسخه‌ی **۲۲٫۵ به بالا** (پیشنهادی: ۲۴) — برای ماژول داخلی `node:sqlite`
- اتصال اینترنت در نخستین اجرا (برای دریافت فونت Vazirmatn از طریق `next/font`).

## نصب و اجرا

```bash
npm install
```

اجرای محیط توسعه:

```bash
npm run dev
```

سپس مرورگر را روی <http://localhost:3000> باز کنید.

ساخت نسخه‌ی تولید و اجرا:

```bash
npm run build
npm run start
```

## متغیرهای محیطی

فایل `.env.example` را به `.env.local` کپی کنید و مقادیر واقعی را بگذارید:

```bash
# دامنه‌ی سایت (canonical، Open Graph، sitemap و robots)
NEXT_PUBLIC_SITE_URL=https://your-domain.ir

# ادمین اولیه — فقط در نخستین اجرا (وقتی دیتابیس خالی است) کاربر ساخته می‌شود
ADMIN_USERNAME=admin
ADMIN_PASSWORD=seirani-admin

# کلید امضای کوکی نشست ادمین — در تولید حتماً یک مقدار تصادفی طولانی بگذارید
ADMIN_SESSION_SECRET=change-me-to-a-long-random-string
```

> در محیط Production، تعریف `ADMIN_PASSWORD` و `ADMIN_SESSION_SECRET` الزامی است
> و برنامه بدون آن‌ها با خطای واضح متوقف می‌شود؛ رمز پیش‌فرض تولید وجود ندارد.

## اجرای نسخهٔ PHP

1. محتوای `php-site/` را روی هاست قرار دهید.
2. `php-site/inc/config.example.php` را با نام `config.php` کپی کنید.
3. مقادیر دیتابیس، رمز ادمین و دامنه را فقط در `config.php` مقصد وارد کنید.
4. دیتابیس MySQL خالی بسازید؛ جدول‌ها در نخستین اجرا ایجاد می‌شوند.

فایل `php-site/inc/config.php` خصوصی است و توسط `.gitignore` هرگز commit نمی‌شود.

## دیتابیس (SQLite)

- محتوای سایت (خدمات، آمار، صحنه‌ها، گره‌های شبکه، متن بخش‌ها، مقالات و
  درخواست‌های تماس) در یک دیتابیس **SQLite** با ماژول داخلی **`node:sqlite`**
  نگه‌داری می‌شود (بدون هیچ وابستگی native یا کامپایل). نیازمند **Node.js ۲۲٫۵ به
  بالا** (پیشنهادی: ۲۴).
- فایل دیتابیس در `data/seirani.db` ساخته می‌شود (در `.gitignore` است).
- در **نخستین اجرا** جدول‌ها ساخته و با محتوای پیش‌فرض `lib/data.ts` پر می‌شوند
  (سایت دقیقاً مثل قبل نمایش داده می‌شود)؛ پس از آن، منبعِ حقیقت دیتابیس است و
  ویرایش از پنل ادمین انجام می‌شود.
- برای شروع از نو کافی است فایل‌های `data/seirani.db*` را حذف کنید.

## پنل ادمین

نشانی: **`/admin`** (ورود در `/admin/login`).

- **ورود** با نام‌کاربری/رمز عبور (کوکی نشست امضاشده با HMAC).
- **مقالات و وبلاگ:** ساخت، ویرایش، انتشار/پیش‌نویس و حذف.
- **خدمات و آمار:** ویرایش کارت‌های خدمات (همراه با **آپلود آیکون برای هر خدمت**)
  و اعداد آماری (با افزودن/حذف ردیف).
- **محتوای بخش‌ها:** ویرایش متن‌های Hero، سرتیتر خدمات/وبلاگ، صحنه‌های «مسیر ما»،
  درباره ما و اطلاعات تماس.
- **درخواست‌های تماس:** مشاهده، علامت‌گذاری خوانده/نخوانده و حذف پیام‌های فرم تماس.

## وبلاگ

- بخش پیش‌نمایش در صفحه‌ی اصلی (`#blog`) با سه مقاله‌ی آخر.
- صفحه‌ی فهرست کامل در `/blog` و صفحه‌ی هر مقاله در `/blog/[slug]`.
- متن مقاله ساده است: خطی که با `## ` شروع شود عنوان، با `### ` زیرعنوان و بقیه
  پاراگراف در نظر گرفته می‌شوند (بدون HTML خام).

## اسکرول تمام‌صفحه

هر بخش یک صفحه‌ی کامل است و با `scroll-snap` روی نمایشگرهای بزرگ، هنگام اسکرول
دقیقاً روی یک بخش می‌ایستد. روی موبایل/نمایشگرهای کوتاه این رفتار خاموش می‌شود تا
محتوای بلندتر از صفحه همیشه در دسترس بماند.

## بخش سئو (SEO)

- متادیتای کامل با Metadata API: `title`/`template`، `description`، `keywords`،
  `canonical`، `robots`، `themeColor`.
- **Open Graph** و **Twitter Card** با تصویر برند‌دار ۱۲۰۰×۶۳۰ (`/og.png`).
- **داده‌ی ساختاریافته** (JSON-LD): `Organization` + `WebSite` + فهرست خدمات.
- `robots.txt` و `sitemap.xml` پویا، و `manifest.webmanifest`.
- زبان و جهت صحیح: `<html lang="fa" dir="rtl">`.
- ساختار معنایی: یک `<h1>`، سرتیترهای `<h2>` برای هر بخش، `aria-label`ها،
  و رندر سمت‌سرور محتوا (شمارنده‌ها مقدار واقعی را برای موتور جستجو دارند).

## نکات فنی

- **RTL:** کل چیدمان راست‌به‌چپ است.
- **اعداد فارسی:** همه‌ی ارقام فارسی و جداکننده‌ی هزارگان «٬».
- **رنگ‌ها:** با `oklch` (مطابق طراحی)؛ نیازمند مرورگرهای مدرن.
- **کاهش حرکت:** با `prefers-reduced-motion` انیمیشن‌ها و پارالاکس غیرفعال می‌شوند.

## امنیت مخزن و انتشار در GitHub

- `.env.local`، `.env`، `php-site/inc/config.php` و تمام فایل‌های دیتابیس ignore هستند.
- فایل‌های ZIP، TAR، بکاپ و dump دیتابیس وارد مخزن نمی‌شوند.
- فقط فایل‌های `.env.example` و `config.example.php` با مقادیر ساختگی منتشر می‌شوند.
- GitHub Actions در هر Push و Pull Request دستورهای `npm ci` و `npm run build` را اجرا می‌کند.
- هیچ رمز، توکن، کلید SSH یا دادهٔ فرم تماس نباید به‌صورت دستی با `git add -f` اضافه شود.

### انتشار اولیه در GitHub

پس از ساخت یک Repository خالی در GitHub:

```bash
git add .
git status
git commit -m "Initial secure release"
git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPOSITORY.git
git push -u origin main
```

پیش از هر Commit، خروجی `git status` را بررسی کنید و مطمئن شوید فایل‌های `.env`،
`config.php`، دیتابیس، ZIP یا بکاپ در فهرست نیستند.

## ⚠️ جای‌گزین‌هایی که باید پیش از انتشار عوض شوند

در `lib/site.ts`:

- `name` — نام شرکت (فعلاً «سیرانی»، برگرفته از نام پوشه؛ **تأیید شود**).
- `contact.address` / `phoneDisplay` / `phoneHref` / `email` — اطلاعات واقعی تماس.
- `NEXT_PUBLIC_SITE_URL` — دامنه‌ی واقعی.

سایر موارد:

- **مبدأ مسیر:** در `lib/data.ts` شهر «تهران» جای‌گیر است (طبق یادداشت طراحی،
  مرز عبور «رازی» است).
- **آمار:** ارقام ۱۲/۳۴/۸٬۴۰۰/۹۸ در صورت نهایی‌نبودن اصلاح شوند.
- **فرم تماس:** اکنون فقط سمت‌کلاینت است (برچسب دکمه عوض می‌شود)؛ به یک endpoint
  واقعی در `components/Contact.tsx` متصل شود.
- **تصویر OG و لوگو/آیکون:** `public/og.png` و `public/assets/logo.jpg`
  با نسخه‌های نهایی برند جایگزین شوند (لوگوی شفاف PNG پیشنهاد می‌شود).
- **ویدیوهای استوک:** `clip-*.mp4` واترمارک دارند؛ در طراحی با
  `transform: scale(1.2)` پنهان شده. برای تولید، فوتیج تمیز/دارای مجوز جایگزین شود.
